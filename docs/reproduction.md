# Reproduction

## Two environments

Generation and training use separate environments because the tested Sionna
release and the original CUDA training stack use different PyTorch versions.
Do not install Sionna into the locked demo/training environment.

| Stage | Tested versions |
|---|---|
| Generation | Python 3.11.15, Sionna 2.0.1, PyTorch 2.12.0, NumPy 2.4.6 |
| Formal training/evaluation | Python 3.10.20, PyTorch 2.6.0+cu124, NumPy 2.2.6; GTX 1650 |
| Portable demo/tests | Python 3.10.20, PyTorch 2.6.0+cpu, NumPy 2.2.6, Gradio 6.32.0 |

The root `uv.lock` pins the CPU environment. The generation environment has its
own project definition under `environments/generation/`.

## Generate and validate data

Run from the repository root. The generator refuses a nonempty dataset directory.

```sh
uv run --project environments/generation --locked python scripts/01b_generate_sionna.py --config configs/data/formal_v1.yaml
uv run --locked --extra train python tools/check_dataset.py data/sionna_causal_v1
```

The recipe creates 8,000 train, 1,000 validation and 500 test sequences for each
of 30, 50, 70, 90 and 120 km/h. Data stay under `data/`, excluded from Git.
Generation seeds are set for Sionna, PyTorch and NumPy. The manifest records the
configuration, library versions, observation policy, normalization scale and
content fingerprint. The checker validates all files, shapes, finite values,
split counts, exact duplicate clean histories and the train-only normalizer.

The published formal run was sealed with these identities:

```text
Experiment: 71297b9718bbfc053762aa89bd88c7094989f9cdd0ee34b3d83657370fc3c73c
Dataset:    88a533c21aca43dfa85a16da51e00b0665dc5a2723e8f6f845919acd08f9042d
```

A new execution records its own identities. Source additions, output-directory
changes and runtime versions change the experiment identity. Identical settings
on another machine do not guarantee identical generated bytes. This repository
uses paths inside the checkout; the sealed run used a separate frozen source
directory and sibling data/results directories. Those path changes do not alter
the channel settings or model configurations.

## Train the matrix

The formal recipe requires CUDA and refuses a silent CPU fallback. For GPU
training, create a separate Python 3.10 environment using the CUDA PyTorch build
appropriate for the recorded stack; install NumPy 2.2.6, PyYAML 6.0.3,
TensorBoard 2.20.0 and tqdm 4.70.1. Do not replace the CPU environment's lockfile
with an export of your whole workstation environment.

```sh
python tools/train_suite.py run --plan configs/experiments/formal_v1.json
python tools/train_suite.py status --plan configs/experiments/formal_v1.json
```

The suite runs every declared seed, selects checkpoints using validation NMSE
and automatically evaluates all completed models. The source/data/config identity
must remain fixed throughout an experiment.

Run the additional learned baselines with the same environment and dataset:

```sh
python tools/train_suite.py run --plan configs/experiments/baseline_v1.json
```

This adds LSTM/GRU/RNN/CNN with three seeds each. The initial 15-run matrix and
the 12-run extension use separate output directories. See [benchmark settings](benchmark.md).

```sh
python tools/train_suite.py stop --plan configs/experiments/formal_v1.json
python tools/train_suite.py run --plan configs/experiments/formal_v1.json --resume
```

Stopping is cooperative: wait until status says `stopped` before terminating the
process. Resume restores model, optimizer, scheduler and RNG state at an epoch
boundary. A single-writer lock prevents simultaneous writers to one output folder.
Changing source, data or configuration requires a new output directory.

## Evaluate and report

```sh
python tools/evaluate_suite.py --plan configs/experiments/formal_v1.json
python tools/report_results.py --evaluation runs/formal-v1/evaluation.json --output runs/formal-v1/report
```

Evaluation requires every declared run and checks checkpoint, source and dataset
identities. Per-sequence/per-horizon linear NMSE arrays are saved for independent
recomputation. All 15 selected formal checkpoints were audited against their
validation histories, and all 75 scenario/seed results were recomputed from
weights without changing the frozen training source.

## Verification scope

To create an inference bundle from your completed run:

```sh
python tools/export_bundle.py --results runs/formal-v1 --data data/sionna_causal_v1 --output artifacts/formal-v1
python tools/smoke_inference.py --bundle artifacts/formal-v1
```

Export requires matching source, dataset and completed checkpoints. It strips
optimizer/RNG state and machine-local training paths. Use an empty export directory.

To export the extension and merge the two compatible bundles:

```sh
python tools/export_bundle.py --results runs/baseline-v1 --data data/sionna_causal_v1 --output artifacts/baselines-v1
python tools/merge_bundles.py --bundles artifacts/formal-v1 artifacts/baselines-v1 --output artifacts/benchmark-v1
python tools/smoke_inference.py --bundle artifacts/benchmark-v1
```

The merge requires identical examples, normalization, observation policy and
model source. Every model retains the identity of its own training experiment.
The benchmark also evaluates four deterministic references once per scenario;
these are not additional neural-network training runs.

Windows CPU unit tests, full exported-weight inference and Gradio prediction
requests have been exercised locally. The GitHub Actions workflow defines Linux
and Windows CPU checks; a workflow file alone is not evidence that a remote run
has passed. CI does not regenerate the full dataset or repeat the formal GPU job.
